# V1.1 button interactions

V1.1 is a complete vertical slice layered on the accepted v1 routing daemon.
None of this document is required for v1 completion.

## Decoded state and events

In addition to v1's connection bit, a successful connected report is decoded
as follows:

| Input | Meaning |
| --- | --- |
| rising edge of `report[39] & 0x08` | volume-up press |
| rising edge of `report[39] & 0x10` | volume-down press |
| rising edge of `report[39] & 0x20` | microphone-mute press |
| `(report[43] & 0xf0) == 0` | microphone muted |
| `(report[43] & 0xf0) != 0` | microphone active |
| `report[44]` | absolute volume, valid only in `0..15` |

The microphone mapping MUST be validated on Olympus firmware 1.38 before v1.1
is released. An out-of-range volume MUST be logged and omitted from normalized
state rather than clamped.

V1.1 normalized state adds optional volume, optional microphone mute, and the
three instantaneous button bits. The daemon MUST log their normalized
transitions as JSON events. A held button MUST produce exactly one press event.
Button-edge history MUST reset on disconnect or device replacement; the first
connected report establishes the button baseline and MUST NOT synthesize a
press.

## Control synchronization

V1.1 adds strict YAML key `controls.enabled` and Home Manager option
`services.pslinkd.controls.enable`. Both are booleans defaulting to `false`.
Decoding and event logging continue when controls are disabled.

When controls are enabled and the headset is connected:

- the first valid volume and each later volume change MUST set the configured
  headset sink volume to `volume / 15` with `wpctl set-volume`;
- the first valid microphone state and each later state change MUST set the
  configured headset source mute state with `wpctl set-mute`, when the optional
  source pair is configured; and
- stale values MUST NOT be applied while disconnected.

These are absolute state-convergence actions, not relative button actions. They
use the same exact-name lookup, current ephemeral ID resolution, bounded command
timeout, desired-action revision, and retry rules as v1 routing.

V1.1 still does not execute arbitrary event hooks, expose IPC, invoke `pactl`,
or forcibly move pinned streams.

## Automated acceptance

Tests MUST cover:

- all decoded fields and out-of-range volume;
- one event per rising edge, no repeats while held, independent simultaneous
  bits, and baseline reset/no synthetic event on connect or replacement;
- JSON events for volume, microphone state, and all three button presses;
- strict config and Nix option defaults/type checking for controls;
- volume mapping for every integer `0..15`;
- initial and changed volume/mute convergence only while connected and enabled;
- no control commands when disabled;
- no source mute command without the optional source pair; and
- retry, recovery, and obsolete-action cancellation for control commands.

## Olympus v1.1 release gates

Before v1.1 is complete on firmware 1.38:

1. Validate all three button bits and exactly one event per physical press.
2. Validate every observed absolute volume level and the linear PipeWire
   mapping with controls enabled.
3. Validate byte-43 microphone polarity and PipeWire source mute convergence.
4. Validate initial volume/mute convergence after daemon start and reconnect.
5. Play sustained audio while repeatedly using every control; feature polling
   MUST NOT destabilize USB audio, PipeWire, or the adapter.
6. Record whether continuous 5 Hz polling changes headset auto-off behavior.

Controls remain disabled by default for v1.1 unless a later spec change chooses
otherwise after these gates pass.
